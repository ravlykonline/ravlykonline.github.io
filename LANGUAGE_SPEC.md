# LANGUAGE_SPEC.md

Це специфікація мови програмування РАВЛИК у її поточному стані. Документ має бути джерелом істини для parser/runtime/manual/tests.

## 1. Призначення мови

РАВЛИК — навчальна текстова мова для дітей. Вона має допомогти перейти від блокового програмування до текстового коду через зрозумілі українські команди, миттєвий візуальний результат і дружні помилки.

Принципи мови:

- простота важливіша за універсальність;
- передбачуваність важливіша за “магічність”;
- кожна помилка має бути пояснена людською мовою;
- однаковий код має поводитися однаково у звичайному та ігровому режимі;
- не можна допускати зависання браузера через коротку програму.

## 2. Лексика

### 2.1. Коментарі

Коментар починається з `//` і триває до кінця рядка. Старий запис через `#`
залишається робочим для сумісності з уже створеними уроками й кодом.

```ravlyk
// Це коментар
вперед 100 // Це теж коментар
вперед 50 # Старий сумісний варіант
```

### 2.2. Рядки

Рядки записуються в подвійних лапках. Поточний tokenizer підтримує рядки без переносу рядка всередині:

```ravlyk
клавіша "ArrowUp"
```

### 2.3. Дужки і розділювачі

Використовуються:

- `(` `)` для блоків, функцій і групування виразів;
- `,` для розділення аргументів;
- `=` для присвоєння і порівняння;
- `!=`, `<`, `>`, `<=`, `>=` для порівнянь.

### 2.4. Числа

Підтримуються числа такого типу:

```text
10
-10
3.14
.5
1e3
-2.5e-2
```

Числа мають бути скінченними. `Infinity`, `NaN` та інші JS-значення не є валідними значеннями мови.

## 3. Ідентифікатори

Ідентифікатори використовуються для змінних, функцій і параметрів.

Поточний код має `isValidParserIdentifier`, але потрібно формально зафіксувати правило.

Рекомендоване правило:

- дозволені українські й латинські літери;
- дозволені цифри після першого символу;
- дозволені `_` і `-`;
- назва не може бути порожньою;
- назва не може збігатися із зарезервованим словом;
- назва нормалізується до нижнього регістру.

## 4. Зарезервовані слова

Зарезервовані слова не можна використовувати як назви змінних, функцій або параметрів.

```text
вперед, назад, праворуч, ліворуч,
колір, фон, товщина, підняти, опустити,
очистити, перейти, повторити, повтори,
поки, стоп, якщо, інакше, створити, грати,
край, клавіша, випадково, в,
вишиванка, звичайний,
чекати, пауза,
сховати, показати, додому,
модуль, корінь,
forward, backward, right, left,
color, background, thickness, penup, pendown,
clear, goto, repeat, while, break, if, else, create, game,
edge, key, random, to,
vyshyvanka, zvychainyi,
wait, hide, show, home,
abs, sqrt
```

Поточний стан: semantic validator забороняє ці слова для назв змінних, функцій і параметрів. `в` / `to` — службові прийменники команди `перейти в X Y`.

### 5.2. Рух назад

### 5.3. Поворот праворуч

```ravlyk

right 90
```

### 5.4. Поворот ліворуч

```ravlyk

```

## 6. Команди стану пера і полотна

### 6.1. Колір пера

```ravlyk
колір червоний
color red
колір випадково
```

Колір має бути в `COLOR_REGISTRY` з `constants.js` або його alias.

### 6.2. Колір фону

```ravlyk
фон білий
background white
фон випадково
```

### 6.3. Товщина лінії

```ravlyk
товщина 5
thickness 5
```

Поточні межі:

```js
MIN_PEN_SIZE = 1
MAX_PEN_SIZE = 50
```

Товщина має бути цілим числом.

### 6.4. Підняти / опустити олівець

```ravlyk
підняти
penup

опустити
pendown
```

### 6.5. Очистити полотно

```ravlyk
очистити
clear
```

`очистити` стирає малюнок, повертає фон до білого, вимикає режим вишиванки, скидає товщину лінії до стандартної і робить Равлика видимим. Позиція, напрямок, перо і колір олівця не змінюються.

AST-вузол: `ClearStmt`.

### 6.6. Видимість і повернення додому

```ravlyk
сховати
показати
додому

hide
show
home
```

- `сховати` робить зображення Равлика невидимим. Рух і малювання продовжують працювати.
- `показати` знову показує Равлика в поточній позиції.
- `додому` повертає Равлика в початкову позицію і початковий напрямок без малювання.
- `додому` не змінює перо, колір, товщину, фон, режим вишиванки або видимість.
- `очистити` додатково робить Равлика видимим.

AST-вузли:

```text
VisibilityStmt { visible: true | false }
HomeStmt
```

### 6.7. Режим вишиванки

```ravlyk
вишиванка
vyshyvanka

звичайний
zvychainyi
```

`вишиванка` вмикає режим вишивки: рухи олівця малюють хрестики (×) замість суцільної лінії, а поточний колір фону отримує текстуру тканини.
`звичайний` повертає звичайний режим малювання і прибирає текстуру, зберігаючи поточний колір фону.

- Ці ключові слова є зарезервованими і не можуть використовуватись як імена змінних чи функцій.
- Команда `фон` завжди задає базовий колір полотна. У режимі `вишиванка` цей колір одразу перемальовується з тканинною текстурою.
- Стан скидається при `очистити` і при кожному новому запуску програми.

AST-вузол: `EmbroideryStmt { mode: 'on' | 'off' }`.

### 6.8. Пауза

```ravlyk
чекати 2
чекати 0.5
чекати 1/2
пауза 1
wait 3
```

Рівлик робить паузу на вказану кількість секунд. Аргумент — числовий вираз; допустимі значення: від `0` до `60` секунд включно. Від'ємні значення та значення понад `60` є помилкою.

- Пауза є семантичною: вона виконується навіть якщо вимкнено анімацію (режим «без анімації» прискорює рух, але не скасовує очікування).
- Всередині блоку `грати (...)` команда заборонена — семантична помилка.
- Aliases: `чекати` / `пауза` / `wait`.

AST-вузол: `WaitStmt { duration: <expr> }`.

### 6.9. Перейти в координату

```ravlyk
перейти 100 50
перейти в 100 50
перейти в 50 -200
перейти 100, 50
goto 100 50
goto to 100 50
перейти випадково
```

**Правила парсингу координат:**

- Без коми → coord-режим: `перейти в 50 -200` читається як x=50, y=−200. Унарний мінус перед числом завжди стартує нову координату.
- З комою → арифметичний режим: `перейти в x+5, y-2` читається як x=x+5, y=y−2. Обидві координати — повні вирази.
- Вирази в дужках і mul/div/mod (`*`, `/`, `%`) працюють в обох режимах: `перейти в (50+10) -200` → x=60, y=−200.

## 7. Вирази

Підтримуються:

- числові літерали;
- змінні;
- унарні `+` і `-`;
- бінарні `+`, `-`, `*`, `/`, `%`;
- математичні функції `модуль(...)` / `abs(...)` і `корінь(...)` / `sqrt(...)`;
- групування дужками.

Приклади:

```ravlyk
створити a = 10
створити b = 20
вперед a + b * 2
вперед (a + b) * 2
вперед -a
вперед модуль(-50)
вперед корінь(100)
```

`модуль(x)` повертає абсолютне значення числа. `корінь(x)` повертає квадратний корінь; для від'ємного числа це дружня runtime-помилка, а не `NaN`.

Поточна проблема: треба явно протестувати ділення на нуль і нескінченні значення. Runtime має відхиляти нескінченний результат дружньою помилкою.

## 8. Змінні

### 8.1. Створення змінної

```ravlyk
створити x = 100
create x = 100
```

### 8.2. Присвоєння існуючій змінній

```ravlyk
x = 200
```

### Правила, які треба зафіксувати

- Змінну бажано створити через `створити` перед першим використанням.
- Не можна називати змінну зарезервованим словом.
- Не можна створювати змінну з назвою вже існуючої функції.
- Повторне `створити x = ...` для тієї самої змінної є помилкою з дружньою підказкою використати `x = нове_значення`. Реалізовано в `semanticValidator.js` (перевіряє поточний і батьківські scope; shadowing параметра функції теж заборонений).

## 9. Цикли

```ravlyk
повторити 4 (
  вперед 100
  праворуч 90
)
```

Alias:

```ravlyk
повтори 4 (...)
repeat 4 (...)
```

Кількість повторів має бути цілим числом `>= 0` і не більше `MAX_REPEATS_IN_LOOP`.

Поточний ліміт:

```js
MAX_REPEATS_IN_LOOP = 500
```

### Важливе уточнення

Ліміт на один цикл не захищає від вкладених циклів. Потрібен глобальний бюджет операцій.

### 9.1. Умовний цикл `поки`

```ravlyk
створити x = 0
поки x < 10 (
  вперед 10
  x = x + 1
)
```

Alias:

```ravlyk
while x < 10 (...)
```

`поки умова ( ... )` перевіряє умову перед кожним повторенням і виконує тіло, доки умова істинна. Умова має той самий формат, що й у `якщо`: порівняння, `край` або `клавіша "..."`.

Команда використовує загальні AST/runtime budgets, тому нескінченний або надто довгий цикл зупиняється дружньою помилкою, а не зависанням браузера.

### 9.2. Вихід із циклу `стоп`

```ravlyk
повторити 100 (
  якщо край (
    стоп
  )
  вперед 10
)
```

Alias:

```ravlyk
break
```

`стоп` виходить лише з найближчого циклу `повторити` або `поки`. Команда не зупиняє всю програму: після циклу виконання продовжується. Якщо `стоп` написати поза циклом, semantic validator показує дружню помилку.

## 11. Функції

### 11.1. Оголошення функції

```ravlyk
створити квадрат(сторона) (
  повторити 4 (
    вперед сторона
    праворуч 90
  )
)
```

### 11.2. Виклик функції

```ravlyk
квадрат(100)
```

### 11.3. Функція з кількома параметрами

```ravlyk
створити прямокутник(ширина, висота) (
  повторити 2 (
    вперед ширина
    праворуч 90
    вперед висота
    праворуч 90
  )
)

прямокутник(120, 60)
```

### Обов'язкові правила

- ✓ Назва функції не може бути зарезервованим словом.
- ✓ Назва функції не може збігатися з назвою змінної.
- ✓ Не можна оголосити дві функції з однаковою назвою.
- ✓ Параметри не можуть дублюватися.
- ✓ Параметр не може бути зарезервованим словом.
- ✓ Кількість аргументів у виклику має точно збігатися з кількістю параметрів.
- ✓ Функція не має бути порожньою.

✓ Повторне `створити x = ...` заборонено semantic validator-ом. Правило: у тій самій scope-лінії змінна може бути оголошена через `створити` лише один раз. `повторити`, `якщо`, `грати` ділять scope з батьком; тіло функції отримує власну scope і може мати власну змінну з тим самим ім'ям.

## 12. Ігровий режим

Команда:

```ravlyk
грати (
  якщо клавіша "ArrowUp" (
    вперед 5
  )
)
```

Alias:

```ravlyk
game (...)
```

### Правила ігрового режиму

- У програмі має бути не більше одного блоку `грати`.
- `грати` має бути тільки на верхньому рівні.
- `грати` не можна вкладати у функції, цикли або умови.
- Якщо є `грати`, на верхньому рівні мають бути дозволені тільки:
  - створення змінних;
  - оголошення функцій;
  - сам блок `грати`.
- У кожному game tick є operation budget `MAX_GAME_TICK_OPERATIONS = 500` AST-кроків.

Поточний semantic validator перевіряє:

- у програмі не більше одного `грати`;
- `грати` тільки на верхньому рівні;
- якщо є `грати`, на верхньому рівні дозволені лише `створити ... = ...`, оголошення функцій і сам `грати`.

Operation budget на game tick реалізовано через параметр `maxAstSteps` у `createAstRuntime` (рахується кожен AST-крок, включно з присвоєннями та control-flow).

## 13. Випадковість

Поточні місця, де підтримується `випадково` / `random`:

```ravlyk
вперед випадково
колір випадково
фон випадково
перейти випадково
```

Правила:

- випадковий рух має не виводити Равлика за межі полотна;
- випадкова точка має бути в безпечній зоні;
- випадковий колір має бути з дозволеного registry;
- тести мають мати можливість підмінити random на deterministic seed або mock.

## 14. Помилки

Усі помилки мають бути дружніми й бажано містити:

- що сталося;
- де сталося: рядок/колонка;
- як виправити.

Технічні помилки типу `RangeError`, `TypeError`, `undefined is not a function` не мають показуватися дитині як основний текст.

## 15. Семантична модель виконання

Рекомендована модель:

1. `source code`;
2. tokenizer;
3. parser -> AST;
4. semantic validator -> checked AST;
5. runtime executes checked AST step by step;
6. renderer/animation layer відображає результат.

Не рекомендовано:

```text
AST -> попередньо розгорнута command queue -> виконання
```

Причина: передчасне обчислення значень змінних може відрізнятися від очікуваної послідовної семантики.

## 16. Мінімальна граматика

Умовна EBNF-форма:

```ebnf
program        = statement* ;
statement      = move | turn | color | background | thickness | pen | clear | goto
               | visibility | home | embroidery | wait
               | assignment | createVar | functionDef | functionCall
               | repeat | whileStmt | breakStmt | ifStmt | gameStmt ;

move           = ("вперед" | "forward" | "назад" | "backward") (expression | random) ;
turn           = ("праворуч" | "right" | "ліворуч" | "left") expression ;
color          = ("колір" | "color") (identifier | random) ;
background     = ("фон" | "background") (identifier | random) ;
thickness      = ("товщина" | "thickness") unsignedInteger ;
pen            = "підняти" | "penup" | "опустити" | "pendown" ;
clear          = "очистити" | "clear" ;
visibility     = "сховати" | "hide" | "показати" | "show" ;
home           = "додому" | "home" ;
embroidery     = "вишиванка" | "vyshyvanka" | "звичайний" | "zvychainyi" ;
wait           = ("чекати" | "пауза" | "wait") expression ;
goto           = ("перейти" | "goto") ["в" | "to"] (coordPair | random) ;
coordPair      = expression "," expression    (* кома-режим: повна арифметика в обох *)
               | coordModeExpr coordModeExpr ; (* coord-режим: unary − стартує y *)
coordModeExpr  = expression (* top-level + / − не поглинаються; дужки і * / % дозволені *) ;

createVar      = ("створити" | "create") identifier "=" expression ;
assignment     = identifier "=" expression ;
functionDef    = ("створити" | "create") identifier "(" [params] ")" block ;
functionCall   = identifier "(" [args] ")" ;
params         = identifier ("," identifier)* ;
args           = expression ("," expression)* ;

repeat         = ("повторити" | "повтори" | "repeat") expression block ;
whileStmt      = ("поки" | "while") condition block ;
breakStmt      = "стоп" | "break" ;
ifStmt         = ("якщо" | "if") condition block [("інакше" | "else") block] ;
gameStmt       = ("грати" | "game") block ;
block          = "(" statement* ")" ;

condition      = "край" | "edge"
               | ("клавіша" | "key") string
               | expression comparisonOperator expression ;
comparisonOperator = "=" | "!=" | "<" | ">" | "<=" | ">=" ;

expression     = unaryExpr (("+" | "-" | "*" | "/" | "%") unaryExpr)* ;
unaryExpr      = ["+" | "-"] primary ;
builtinCall    = ("модуль" | "abs" | "корінь" | "sqrt") "(" expression ")" ;
primary        = number | builtinCall | identifier | "(" expression ")" ;
random         = "випадково" | "random" ;
```

## 17. Тести відповідності специфікації

Кожна команда має мати тести:

- parser acceptance;
- parser rejection;
- semantic validation;
- runtime behavior;
- friendly error message.

Рекомендований файл:

```text
tests/unit/language-spec.test.js
```

## 18. Відкриті рішення

1. ✓ Повторне `створити x = ...` заборонено із дружньою помилкою та підказкою використати `x = нове_значення`.
2. ✓ Animation path більше не будує flat command queue. `interpreterAstAnimationRuntime.js` використовує `createAstRuntime.step()` — lazy, без попереднього розгортання. Бюджет `maxAstSteps = MAX_COMMAND_QUEUE_LENGTH` захищає від зависання навіть у control-flow-only циклах.
3. ✓ Звичайний режим і game mode обидва використовують `createAstRuntime` для обходу AST — змінні, функції, умови і помилки мають однакову семантику. Верифіковано крос-шляховими тестами у `tests/runtimeUnification.test.js`.

`astProgramToLegacyQueue` / `runCommandQueueRuntime` залишені як **legacy compatibility API** для `parseTokens()` і старих тестів, але не є частиною production execution path.

## 19. План впровадження нових команд

Цей план фіксує порядок розвитку мови після стабілізації базового runtime. Нові команди додаються малими кроками: спочатку специфікація й тести, потім parser/runtime/manual.

### 19.1. `поки` + `стоп` ✓

Реалізовано: умовний цикл і вихід із циклу.

```ravlyk
поки x < 10 (
  вперед 10
  x = x + 1
)

повторити 100 (
  якщо край (
    стоп
  )
  вперед 10
)
```

Рішення:

- `поки умова ( ... )` виконує тіло, доки умова істинна.
- `стоп` виходить лише із найближчого циклу (`поки` або `повторити`), а не з усієї програми.
- `поки` і `стоп` мають працювати в звичайному режимі та в `грати`, з тими самими runtime-лімітами.
- Нескінченні або надто довгі цикли мають зупинятися дружньою помилкою через наявні AST/runtime budgets.

Definition of Done:

- ✓ оновлено grammar у цьому файлі;
- ✓ додано parser acceptance/rejection tests;
- ✓ додано runtime tests для `поки`, вкладених циклів і `стоп`;
- ✓ додано regression tests на budget/stop responsiveness;
- ✓ оновлено `manual.html` і коротку підказку на `index.html`.

### 19.2. Математичні функції `модуль` / `корінь` ✓

Реалізовано: розширення числових виразів.

```ravlyk
вперед модуль(-50)
вперед корінь(100)
```

Aliases:

```ravlyk
abs(-50)
sqrt(100)
```

Рішення:

- ✓ `модуль(x)` / `abs(x)` повертає абсолютне значення числа.
- ✓ `корінь(x)` / `sqrt(x)` повертає квадратний корінь.
- ✓ `корінь` для від'ємного числа є дружньою runtime-помилкою, а не `NaN`.
- ✓ Функції доступні тільки всередині виразів, не як окремі команди.

### 19.3. `випадково(від, до)`

Третій пріоритет — контрольована випадковість:

```ravlyk
вперед випадково(10, 100)
праворуч випадково(30, 120)
```

Рішення:

- Поточне слово `випадково` без аргументів лишається сумісним для руху, кольору, фону й `перейти`.
- `випадково(a, b)` працює як числова функція у виразах і повертає число в діапазоні від `a` до `b`.
- Перед реалізацією треба прийняти parser-рішення для function-like built-ins: або `випадково(...)` стає частиною expression parser як вбудована числова функція, або вводиться окремий AST-вузол для випадкового числа з аргументами. Це рішення має зберегти сумісність із поточним `випадково` без дужок.
- Якщо межі некоректні або результат не є скінченним числом, runtime показує дружню помилку.

### 19.4. Стан Равлика: `кут`

Четвертий пріоритет — обережно додати читання стану:

```ravlyk
якщо кут > 90 (
  праворуч 10
)
```

Рішення:

- Почати лише з `кут`, бо це зрозуміле українське слово і менш ризиковане, ніж координати.
- `кут` має бути вбудованим значенням середовища виконання, а не зарезервованим словом.
- Якщо користувач створив власну змінну `кут`, вона може затінити вбудоване значення.
- Координати `х` / `у` не додавати, доки не з'явиться сильна навчальна потреба.

### 19.5. Не робити зараз

Поки не додавати:

- повернення значень із функцій (`return`) — це суттєво ускладнює модель мови;
- текст на полотні — корисно, але не критично для ядра;
- `sin` / `cos` — відкласти до моменту, коли `модуль`, `корінь` і `випадково(від, до)` стабільні.

## 20. Definition of Done для мови

Мову можна вважати стабільною, коли:

- `LANGUAGE_SPEC.md` відповідає реалізації;
- усі правила covered тестами;
- звичайний режим і game mode мають однакову семантику;
- усі помилки мають дружні повідомлення;
- неможливо зависити браузер короткою програмою;
- додавання нової команди вимагає оновлення spec, parser, runtime, tests і manual.
