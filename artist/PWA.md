# PWA.md — офлайн і кеш «Равлика Художника»

У гри немає власного Service Worker і маніфесту: `/artist/` обслуговується **кореневим** Service Worker сайту (`/sw.js`, scope `/`, реєстрація лише на production-хості — див. кореневий `PWA`-опис у `README.md`).

## Що це означає

- Файли `/artist/js/*.js` (і інші дозволені розширення) кешуються runtime cache-first за **незмінними URL**. Нова версія гри дійде до користувачів лише після зміни release-токена кореня.
- Тому: після будь-якої зміни в `artist/` (js, css, html) перед деплоєм

  ```bash
  npm run release:sync-version -- YYYY-MM-DD-N
  npm run check
  ```

  (`release-version.json` → кеші й версії URL у статичних точках входу; див. `../RELEASE_CHECKLIST.md`).
- `sitemap.xml` не чіпаємо: `/artist/` поки поза індексом.
- Кеш не містить персональних даних: гра нічого не зберігає (без `localStorage`).
- Після першого завантаження гра працює офлайн лише якщо файли потрапили в runtime-кеш (для цього сторінку треба один раз відкрити онлайн і пройти по ній). Окремого офлайн-списку для artist немає — це ідея в `TASKS.md`.

## Чого не робити

Не додавайте в `artist/` власний `sw.js` чи `manifest.json` без рішення власника: два Service Worker на одному scope конфліктують.
